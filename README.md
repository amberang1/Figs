# In Other Words
A local-first, mobile-first fiction workspace using your own NanoGPT API key. The archive is never replaced by a summary.

## Host and open
- `index.html` is the single-file frontend. Serve it over HTTPS. Direct mode requires NanoGPT browser CORS (not verified live).
- For a same-origin proxy, deploy the entire folder to Cloudflare Pages via Git integration: no build command, output directory `.`, Functions enabled. The included `functions/api/nano.js` forwards only fixed NanoGPT model/completion endpoints. Select **Same-origin Cloudflare Pages proxy** in settings. Dashboard drag-and-drop does not deploy Functions; use Git integration or Wrangler. No deployment has been performed.
- On iPhone/iPad, visit the hosted URL in Safari; optionally Share > Add to Home Screen. No offline service worker or cloud sync.

## First use
1. Create a separate spending-limited NanoGPT API key. Open **API & writing settings** from the library. Enter your key, load live model IDs, and choose the writing model and separate memory model. The key stays in RAM only, and must be re-entered when reloading. Never commit it. Confirm subscription eligibility and actual context/output limits in NanoGPT. Defaults: 16,384 generated tokens, 262,144 writing context, 65,536 memory context.
2. Enable automatic memory (default for new installs), choose 10K, 25K (default), or 50K estimated new prose tokens per batch. A separate memory model is required; the app never silently substitutes the writing model. Extraction is an additional API request, consuming quota or credits. Existing saved settings are preserved.
3. Set reusable writing instructions if desired. **New story** accepts an optional title and opening idea; the idea remains a draft until Write. New stories may inherit the reusable instructions. Import existing Chatbox JSON or In Other Words exports (including legacy Elsewrite exports) instead. Verify imported messages; actual Chatbox export format not tested. Attachments/thinking traces not imported.
4. Write in Story mode (continuous prose with directions and actions available from each reply’s ••• menu), or toggle Reader mode using the header icon for distraction-free reading. Use Continue or enter your own direction. Chat mode and preset director shortcuts have been removed; saved Chat views automatically open in Story mode. Story settings allow smart/full/recent context, a per-story writing model override, story-specific sampling and desired output length (model context capacity remains model-specific), bible and context budgets. New smart-mode stories target 40K input and up to 22K recent verbatim; the recent budget is a ceiling, not a target, when older timeline summaries need room. Short stories send complete history if it fits.
5. Use Regenerate or Edit to archive later messages, not delete them. Branch creates an independent copy up to the selected scene, with source-valid memory. Remember pins a note linked to a scene. Favourites and library search help organise stories.
6. Open the memory inspector to see estimated input, chronological scene-linked timeline, original sources and full archive. Smart context sends the entire active transcript while it fits the input budget. Otherwise it prioritizes **all available older scene timeline entries** before adding more complete recent responses, while retaining the newest scene and its immediately preceding direction when possible. Original excerpts only use leftover space. Preview displays `included / available older timeline entries`, plus warnings for scenes without summaries or summaries that cannot fit. Increase the input budget if the timeline is too long. The Recent-only and Full modes retain their own behavior. Memory extraction requires a separate configured model, processes small batches and can be updated manually. Rebuild is resumable using checkpoints after each completed batch. Completed checkpoint entries now serve as provisional timeline references when their sources still belong to the active story, even before the full rebuild is committed. Legacy timeline notes with unambiguous assistant source IDs are also recognized. Summaries whose sources belong only to archived/replaced scenes are excluded; the app reports how many exist and provides a shortcut from Next request to Story memory. If no eligible timeline exists, Smart adds a few labeled original older-scene excerpts as a temporary, incomplete fallback rather than silently dropping all older reference material. Existing stories and source-linked notes remain intact; manual edits to a scene summary take precedence over duplicate generated entries. Memory calls consume quota or credits. Only active, completed story messages enter context. No embeddings or cloud sync.
7. Export backups regularly. IndexedDB storage is device/origin-specific and unencrypted; browser eviction/clearing can erase stories. No cloud sync or authentication. The chosen provider receives the selected context and the proxy (if used) handles requests in transit. No intentional server logging or persistence in the included proxy.

## Verification and limitations
JavaScript syntax and mocked core tests passed: short-story full context, input cap, threshold batching, inclusion of author directions, independent memory model, incremental source-linked extraction and invalidated source exclusion. Browser navigation in the test environment was blocked by administrator policy; UI and live NanoGPT API integration remain unverified. Token estimates are character-based, not exact model token counts. Reasoning and provider overhead may require larger reserves. 10K visible prose cannot be guaranteed by max_tokens. Retrieval can miss subtle relationships, and extraction can omit or misstate details. No semantic retrieval, reusable character-universe manager, or automatic cloud sync yet. This is a working-source prototype, not a deployed or production-audited service.

### GitHub Pages quick preview
In repository Settings → Pages, select Deploy from a branch, main / (root), then Save. GitHub Pages serves the frontend only; select Direct to NanoGPT. For the same-origin proxy, connect this repository to Cloudflare Pages instead.


### Connection test and billing safety
Use Settings → Test API for a small real completion (up to 64 generated tokens; may consume quota or balance). Writing and memory now default to the subscription-only API; choose All models explicitly for premium models. The API key is session-memory only. GitHub Pages is direct mode only; Cloudflare Pages can use the included proxy. The browser must permit cross-origin access for direct mode. No automatic retry or paid fallback is performed.

The app was formerly named Elsewrite. Its existing local database and backup format identifiers are intentionally unchanged so existing stories and backups remain compatible.

### Story-specific generation preferences
Existing stories migrate their current model's sampling settings and desired output limit into the story. Switching models preserves those values, as do branches and story exports. The effective output can be reduced by known provider limits or context capacity without changing the story's desired output. Global model profiles provide defaults for newly created stories. Some providers reject or ignore unsupported sampling settings; no live provider test was performed.

### Response versions and editing
Regenerating or editing an output creates another version of the same response. Swipe horizontally on a response (right for the previous version, left for the next) or use the version arrows. Selection changes the active response and restores its corresponding prompt; only the active timeline and source-valid notes are sent to the writing model. Selecting an earlier response version prompts before archiving later writing. Archived continuations remain in the full archive; switching versions does not automatically restore those continuations. Story actions > Edit story lists searchable outputs and opens a large multiline editor. Saving is local, creates a new version and makes no API call; optionally keep later responses for minor edits. Versions are included in exports. Older adjacent archived responses with an unambiguous shared prompt are migrated; other legacy archives are kept but not guessed into version groups. Touch interaction and editor layout have not been tested on a physical iPhone.
